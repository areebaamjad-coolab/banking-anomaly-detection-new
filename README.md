## Features

- **Polars** for all CSV loading and reading
- **Local CSV database** — single master file: raw transactions + features + customer profile + demographics
- **Account-level train/test partition** (by `account_id`, chronological account ordering)
- **No labels required** — fully unsupervised evaluation
- **Annexure D output** (CSV + Excel) per model
- **IF hyperparameter grid**: contamination × n_estimators × max_features (45 combos)
- **Feature categories** now grouped as:
  - Amount and balance: transaction amount, balance, and account balance trend features
  - Device, channel/network, and beneficiary: channel, beneficiary, and related network features
  - Velocity and timing: count, ratio, growth, and timing-based behavioral features
  - Demographic and customer profile: customer profile, account profile, and demographic characteristics
- **Numeric vs categorical handling**: numeric features are standardized, while categorical features are label-encoded before model training

## txn_timestamp rules (from column list)

1. Convert to datetime on load
2. Sort by account_id, then txn_timestamp
3. **Partition by account_id** — 80% of accounts → Train, 20% → Test (no account in both)
4. **Never pass txn_timestamp to the model**

## Models

One-Class SVM is a boundary-based anomaly detector that learns a decision region around the normal data. Points that fall outside that region are treated as anomalies, which makes it useful for spotting unusual or rare behavior.

| Model | Score | Threshold |
|-------|-------|-----------|
| Isolation Forest | -score_samples | contamination percentile |
| LOF | -score_samples | contamination percentile |
| One-Class SVM | -decision_function | contamination percentile |
| Autoencoder | MSE reconstruction error | mean + Z_THRESHOLD × std |

**Threshold_2** uses second tier from `Z_THRESHOLD_TIERS` (4.0σ).

## Evaluation approach

Stand-alone strategies rely only on each algorithm and its output without considering other algorithms, so it is possible to understand whether a specific algorithm works well. Excess Mass (EM), Mass-Volume (MV), and Internal Relative Evaluation of Outlier Solutions (IREOS) are stand-alone evaluation metrics.

Conversely, consensus-based metrics help compare different algorithms together and understand which algorithms perform better than others. Consensus-based algorithms are: Unsupervised Disentanglement Ranking (UDR), ModelCentrality (MC), and Model Centrality by HITS.

## Limitations (v1)

- Device, risk indicators, peer group, cash transaction features not included (per Excel note)
- Rolling window features use Polars rolling approximation when computing from raw txn
- IF grid search (45 combos) can be slow on large datasets
- PyTorch optional; sklearn AE used when torch not installed
